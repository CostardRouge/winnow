# Agent commands — the registry and the MCP server

Read when you touch `src/lib/commands/`, `src/scripts/mcp.ts`, or anything that would let a script or an agent DRIVE the library.

## Every agent-facing verb is a COMMAND, with Atelier's shapes (2026-10-09)

**Decision.** The maintainer asked for LightCraft's idea (`storytold/lightcraft`: every gesture a command with a stable dotted id and JSON params, one dispatch door for UI, CLI and MCP) in all three of his projects, on ONE set of conventions so an agent finds the same shapes everywhere. `src/lib/commands/registry.ts` is a port of Atelier's `src/shared/commands/registry.ts` (`docs/memory/agent-commands.md` there): `{id, title, description, params, available, run}`; params a small typed subset (number with min/max/integer, string with enum, boolean, strings, object) → JSON Schema by `paramsJsonSchema`; out of range REFUSED, never clamped; an unknown key refused naming the known ones; `available()` answers `true` or the REASON; errors coded `unknown · unavailable · invalid · failed`; a picture is an `ImageResult` (`kind: 'image'`, base64).

**Where it differs, on purpose**: `available()` may be async (a Winnow command asks the instance whether the Timeline is on or the token may write), so `list()` is async; there is no `subscribe`/`waitForCommand` (nothing mounts here); `ImageResult.mimeType` also takes `image/webp`, Winnow's derivative format. **How to apply**: keep the two files' shapes in step — a new param type or error code is added to Atelier's and this one together, or an agent driving both meets two dialects.

## The MCP server is a CLIENT of the API, not an endpoint inside Winnow (2026-10-09)

**Decision.** Of the two shapes on the table — (a) a stdio MCP server that calls Winnow's HTTP API with an app token, (b) a streamable-HTTP MCP endpoint served by Winnow behind its auth — (a) was chosen, for security first: every command (`src/lib/commands/winnow.ts`) is a request to the very route the UI's gesture calls, so the token's ceiling, the API-only rule, `authz.ts`'s policy, the feature flags (a disabled Timeline 404s) and the routes' own validation apply unchanged, with no second authorization path to drift from the first and no new surface on the internet. (b) would have needed each command to re-derive its rights (or map itself onto a route's `requiredRole`), plus an endpoint exposed through the tunnel. It is also the shape Atelier's bridge has (a local process, three generic tools). Its cost: the maintainer's machine needs a checkout with `node_modules` (the server runs through the `tsx` already in dependencies).

**How to apply.** A new command calls an existing route through `WinnowClient`; if no route does the thing, the route comes first (with its `authz.ts` rule), then the command. `available()` only PREDICTS a refusal from `app.status` (cached 30 s) so the agent is not offered a verb its token cannot use — the server is still the judge. Answers are trimmed (`summarize`: a grid row is ~2.5 KB); `assets.get` is the whole row. `capture_date` reaches JSON as `"…T00:00:00.000Z"` (node-postgres turns a SQL date into a Date at the server's midnight, the instance runs UTC) — slice, never `new Date()` it.

**v1 command set**: `app.status`, `library.days` (calendar route, ≤ 366 days a call), `library.chapters` (Timeline; unavailable while the flag is off — it is off on the instance), `assets.list` (gallery route, `collapse=1` by default, `fold: pairs` for every frame of a pile), `assets.get`, `assets.look` (thumb ~400 px, or proxy ~2048 px with `detail`; WebP as is, size read from the header by `imageSize.ts` — the client carries no sharp), `cull.set` (the grid's `PATCH /api/assets/:id/rating`: verdict, stars, colour). Colour labels are held to Lightroom's five + `none` because `color_label` is free text and no screen writes it yet. Not in v1, each a decision: bulk rating / a whole pile (`/api/ratings/bulk`, `expand_bursts`), tags, trash, geotag, export.
