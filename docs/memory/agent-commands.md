# Agent commands — the registry and the MCP server

Read when you touch `src/lib/commands/`, `src/scripts/mcp.ts`, or anything that would let a script or an agent DRIVE the library.

## Every agent-facing verb is a COMMAND, with Atelier's shapes (2026-10-09)

**Decision.** The maintainer asked for LightCraft's idea (`storytold/lightcraft`: every gesture a command with a stable dotted id and JSON params, one dispatch door for UI, CLI and MCP) in all three of his projects, on ONE set of conventions so an agent finds the same shapes everywhere. `src/lib/commands/registry.ts` is a port of Atelier's `src/shared/commands/registry.ts` (`docs/memory/agent-commands.md` there): `{id, title, description, params, available, run}`; params a small typed subset (number with min/max/integer, string with enum, boolean, strings, object) → JSON Schema by `paramsJsonSchema`; out of range REFUSED, never clamped; an unknown key refused naming the known ones; `available()` answers `true` or the REASON; errors coded `unknown · unavailable · invalid · failed`; a picture is an `ImageResult` (`kind: 'image'`, base64).

**Where it differs, on purpose**: a `numbers` param type (a list held item by item to a number's bounds, and to `maxItems`) exists for bulk verbs on asset ids — added here first, Atelier's session told to add the same;  `available()` may be async (a Winnow command asks the instance whether the Timeline is on or the token may write), so `list()` is async; there is no `subscribe`/`waitForCommand` (nothing mounts here); `ImageResult.mimeType` also takes `image/webp`, Winnow's derivative format. **How to apply**: keep the two files' shapes in step — a new param type or error code is added to Atelier's and this one together, or an agent driving both meets two dialects.

## The MCP server is a CLIENT of the API, not an endpoint inside Winnow (2026-10-09)

**Decision.** Of the two shapes on the table — (a) a stdio MCP server that calls Winnow's HTTP API with an app token, (b) a streamable-HTTP MCP endpoint served by Winnow behind its auth — (a) was chosen, for security first: every command (`src/lib/commands/winnow.ts`) is a request to the very route the UI's gesture calls, so the token's ceiling, the API-only rule, `authz.ts`'s policy, the feature flags (a disabled Timeline 404s) and the routes' own validation apply unchanged, with no second authorization path to drift from the first and no new surface on the internet. (b) would have needed each command to re-derive its rights (or map itself onto a route's `requiredRole`), plus an endpoint exposed through the tunnel. It is also the shape Atelier's bridge has (a local process, three generic tools). Its cost: the maintainer's machine needs a checkout with `node_modules` (the server runs through the `tsx` already in dependencies).

**How to apply.** A new command calls an existing route through `WinnowClient`; if no route does the thing, the route comes first (with its `authz.ts` rule), then the command. `available()` only PREDICTS a refusal from `app.status` (cached 30 s) so the agent is not offered a verb its token cannot use — the server is still the judge. Answers are trimmed (`summarize`: a grid row is ~2.5 KB); `assets.get` is the whole row. `capture_date` reaches JSON as `"…T00:00:00.000Z"` (node-postgres turns a SQL date into a Date at the server's midnight, the instance runs UTC) — slice, never `new Date()` it.

**v1 command set**: `app.status`, `library.days` (calendar route, ≤ 366 days a call), `library.chapters` (Timeline; unavailable while the flag is off — it is off on the instance), `assets.list` (gallery route, `collapse=1` by default, `fold: pairs` for every frame of a pile), `assets.get`, `assets.look` (thumb ~400 px, or proxy ~2048 px with `detail`; WebP as is, size read from the header by `imageSize.ts` — the client carries no sharp), `cull.set` (the grid's `PATCH /api/assets/:id/rating`: verdict, stars, colour). Colour labels are held to Lightroom's five + `none` because `color_label` is free text and no screen writes it yet. `cull.setMany` (2026-10-09) is the bulk gesture, ≤ `MAX_BULK` = 500 ids a call so a runaway loop writes a page, not the library; `wholePile` maps to `expand_bursts`. `tags.assign` (2026-10-09) is the grid's tag gesture; `asset_tags` records no author, so an agent's tags are NOT marked — adding a `tagged_via` would be the next migration if that question gets asked.

## The MCP server: three generic tools over stdio, protocol pure (2026-10-09)

**Decision.** `src/lib/commands/mcp.ts` holds the protocol (JSON-RPC message → answer, no I/O, tested); `src/scripts/mcp.ts` only wires stdin/stdout and the two CLIENT variables `WINNOW_HOST` / `WINNOW_TOKEN` (the same names cloud sessions already use to reach the instance). The tools are Atelier's three under Winnow's name — `winnow_status`, `winnow_commands`, `winnow_run` — not one tool per command, because that is the shared convention and because availability (a read-only token, the Timeline off) belongs in the listing. A refused command is a TOOL result with `isError` and its code, never a JSON-RPC error, so the agent reads the reason. **Traps**: stdout is the protocol channel — never launch it through `npm run` (its banner lands on stdout), log to stderr; it reads no `lib/config.ts` (the instance's schema is not this process's — the one sanctioned `process.env` read outside config, argued in the file); `WINNOW_HOST` must be https except to localhost, the token being a key to an account; on stdin close it drains in-flight answers before exiting. Users › App tokens prints the `claude mcp add … --scope user` line for an agent's token, so the key lands in `~/.claude.json`, never in a committed `.mcp.json`.

**Verified** (2026-10-09): the reads against the live instance with the cloud session's token; the write end to end on a local `next start` — an agent token's `cull.set` stored `rated_via = 'agent'`, a viewer agent token was told why before sending and refused by the proxy after.
